# Excel 文書理解パイプライン

## なぜ普通に読んではいけないか

人間向け Excel 文書では、意味が**セルの値ではなくレイアウト**に埋め込まれている。
罫線で囲った塊が「表」、結合セルが「見出し」、黄色が「変更箇所」、矢印が「遷移」、
コメントが「レビュー指摘」であり、これらは `cell.value` には一切現れない。
テキスト抽出だけで読むと、方眼紙 Excel は意味不明な単語の羅列になる。

このスキルは、人間と同じ経路（見た目）と機械の経路（座標つき構造）の**両方**で読み、
出力をスキーマに固定し、元データと突き合わせて誤読を潰す。

## パイプライン

```
入力 xlsx
  │
  ├─ 1. 構造抽出  scripts/dump_excel.py   → dump/<sheet>.json, .md, index.json
  ├─ 2. 画像化    scripts/render_excel.py → render/<sheet>-<page>.png
  │
  ├─ 3. 目次と種別判定（index.json + 各 .md の冒頭を読む）
  ├─ 4. ハイブリッド読解（画像でレイアウト、ダンプで正確な値）→ structured/<sheet>.json
  ├─ 5. 検証      scripts/verify_extraction.py → 未確認値を潰す
  └─ 6. 納品      structured/*.json + report.md
```

作業ディレクトリは `<作業場所>/excel-doc/<ファイル名>/` を切り、
`dump/` `render/` `structured/` を並べる。ユーザーがアップロードした元ファイルは編集しない。

### 1. 構造抽出

```bash
python <skill>/scripts/dump_excel.py input.xlsx work/dump
```

得られるもの（シートごと）:
- `.json`: 全セル（座標・値・数式・塗り色・文字色・太字・取消線・罫線・コメント・ハイパーリンク）、
  結合範囲、**罫線の連結成分として検出した領域**（表・枠の候補）、図形と矢印（接続元⇒接続先を解決済み）、
  凡例候補、塗り色の使用分布、非表示行列、入力規則、テンプレート種別の推定
- `.md`: 空行空列を落としたグリッド表示。`[#FFFF00]` のような色タグ、`⟶n列結合`、`💬コメント` を付与
- `index.json`: 全シートの一覧（非表示シート含む）とセル数・図形数・種別推定

まず `index.json` を読み、次に各シートの `.md` を読む。`.json` は値を正確に引くときに
`grep` や `python -c` で該当座標だけ引く（大きいので丸ごと読まない）。

### 2. 画像化

```bash
python <skill>/scripts/render_excel.py input.xlsx work/render --dpi 110
```

1シート=1PDF→PNG。横1ページに収め、**行番号・列記号を印字**しているので、
画像上の位置とダンプの座標（例: `K11`）を突き合わせられる。
図形・矢印は openpyxl を通すと消えるため、このスクリプトは zip 内の XML を直接書き換えて描画している。

- 細かい文字が潰れて読めない → `--dpi 160` で再描画、または `--no-fit` で元の改ページのまま出す
- 非表示シートは描画しない（`--include-hidden` で含められる）。非表示シートに本文があるケースは稀だが、
  `index.json` の `state` を見て必要なら含める
- `soffice` が無い環境ではこの段階を飛ばし、ダンプのみで進める（精度が落ちることを report.md に明記）

### 3. 目次と種別判定

`index.json` の `template_guess` は文字列ヒューリスティックの推定にすぎない。
各シートの `.md` 冒頭（タイトル行・見出し行・凡例候補）を見て自分で確定する。
種別ごとの出力スキーマと読み方の注意は `references/templates.md` にある。該当するものを読む。

判断材料:
- 「変更履歴」「改訂履歴」「表紙」「目次」シートはメタ情報として扱い、本文とは分ける
- 1シートに複数の表が並んでいることは普通にある。`regions`（罫線領域）がその単位
- 凡例（「黄色=変更」「◎=必須」）はシート内のどこかに書かれていることが多い。
  `legend_candidates` と、タイトル付近・右上・末尾を探す。見つけた凡例は読解ルールとして固定する

### 4. ハイブリッド読解

シートごとに、画像（`Read` で PNG を開く）とダンプの `.md` を**両方**見てから構造化する。
役割分担を明確にする:

- **画像から読む**: 何がどこに配置されているか、矢印が何と何を結ぶか、色分けの意味、
  フロー・レイアウト図・画面イメージといった空間的な意味、罫線で作った表の列構造
- **ダンプから読む**: 文字列・数値・ID・型名・桁数・物理名の**正確な値**。
  画像は「それらしい」誤読（`order_date`→`order_dale`、`0`/`O`、全角半角）をするので、
  値は必ずダンプから引く

出力は `references/templates.md` のスキーマに沿った JSON。共通ルール:

- すべてのレコードに `source_range`（元のセル範囲）を持たせ、後で人が辿れるようにする
- 元文書に書かれていないことを補完しない。空欄は `null`。推測が必要な箇所は値ではなく
  `unresolved` 配列に「何が読めなかったか」を書く
- 凡例から導いた属性（`changed: true` など）は、どの色/記号から導いたかを `_meta.legend` に残す
- 図形の矢印は `flow` として from/to を記録する。コネクタの接続先が解決できていない矢印は、
  画像とアンカー座標から判断し、確信が持てなければ `unresolved` に送る
- セルのコメントは `review_comments` として座標つきで残す。レビュー指摘や未決事項であることが多い
- 取消線・赤字・黄色など「変更」を表す書式は、凡例の定義に従って `changed` / `deleted` に変換する

数千セルの大きなシートは `regions` 単位で分けて処理する。1領域=1表として順に構造化し、
最後にシート単位の JSON にまとめる。

### 5. 検証

```bash
python <skill>/scripts/verify_extraction.py work/structured/<sheet>.json work/dump --sheet "<シート名>"
```

構造化 JSON の全ての葉（文字列・数値）が、元の Excel のセル値・図形テキスト・コメントの
どこかに存在するかを突き合わせ、存在しないものを列挙する（全角半角・空白は無視）。

- 指摘された値は必ずダンプの `.json` で元セルを引き直す。誤読なら修正、要約や正規化で
  意図的に変えたなら `notes` に理由を書く（`notes`/`summary` 等の自由記述キーは検証対象外）
- 終了コード 0 になるまで、または残りが「意図的な変換」だけになるまで繰り返す
- スキーマ上の必須項目（画面IDやテーブル物理名など）が `null` のままなら、画像をもう一度見る

### 6. 納品

`work/structured/*.json` と `work/report.md` を成果物として送る（`SendUserFile`）。
`report.md` の構成:

```
# <ファイル名> 読解レポート
## 文書の概要（何の文書か、シート構成、1〜3文）
## シート別の内容（種別・主要な表・件数・凡例の解釈）
## 検証結果（突き合わせ件数、未確認として残った値とその扱い）
## 要確認事項（読めなかった箇所、矛盾、凡例が不明な色、非表示シートの扱い）
## 成果物一覧
```

ユーザーの依頼が「要約して」「〜を教えて」のような会話的なものなら、構造化 JSON は作りつつ、
回答本文は会話で返す。JSON は「必要なら使ってください」として添える。

## よくある落とし穴

- **数式セル**: `formula` と `value`（キャッシュ値）を両方持つ。openpyxl 以外で保存された直後の
  ファイルは `value` が空のことがある。その場合は数式を意味として読む
- **1セル1文字の方眼紙**: `.md` のグリッドは空列を落とすので、見た目より列が詰まる。
  列の対応は `⟶n列結合` タグと画像で確認する
- **表が横に2つ並んでいる**: `regions` が2つに分かれていればそれぞれ独立の表。
  1つの領域にまとまっていたら画像で切れ目を判断する
- **白文字・白背景で隠した注記**: `font_color` が `#FFFFFF` のセルはダンプには残る。
  画像には出ないので、ダンプで気づいたら `unresolved` ではなく `hidden_notes` として報告する
- **テーマ色** (`theme:4/tint0.6` のような値): RGB に解決できない。同じテーマ色同士で
  グルーピングし、意味は凡例または画像の見た目で判断する
- **複数ファイル・複数シートにまたがる参照**（「詳細は○○シート参照」）: `cross_references` に
  記録し、同じ依頼の中で参照先も処理する
- **巨大シート** (`truncated: true`): `--max-cells` を上げるか、`--sheets` で分割する
- **Excel 以外**（.xls, .csv, Google スプレッドシート）: .xls は `soffice --convert-to xlsx` で変換してから。
  CSV はレイアウト情報が無いので通常の表として読めばよく、このスキルの対象外
