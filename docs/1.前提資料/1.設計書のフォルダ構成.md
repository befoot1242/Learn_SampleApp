# 設計書のフォルダ構成

## 目的

資料を目的ごとに分類し、要件、基本設計、詳細設計、参考資料をたどれるようにする。番号はフォルダの表示順を示す。

## 各フォルダの役割

| フォルダ | 役割 |
|---|---|
| `1.前提資料/` | 資料の構成と、設計書に記載する内容を定義する。 |
| `2.要件資料/` | システムに求める機能・品質・制約を記載する。要件案と、確定済みの要件を混同しない。 |
| `3.基本設計/` | システム全体の構成・機能・画面・外部インターフェースなど、全体像を記載する。 |
| `4.詳細設計/` | API、DB、セキュリティ、外部API、処理フロー、トランザクション、各画面の仕様を記載する。 |
| `9.その他資料/` | 設計書を補助する画像などと、既存資料の記載状況の評価を格納する。 |

## 配置ルール

- 資料は、主に扱う内容に最も近いフォルダに一度だけ配置する。別の分類から参照するときはリンクを使い、複製しない。
- `README.md` はそのフォルダ内の資料一覧・読み方を案内する。
- 画面キャプチャとワイヤーフレームは `9.その他資料/images/` に置き、設計書から相対リンクする。
- リポジトリルートの `README.md` と `CLAUDE.md` は開発時の案内資料としてルートに残す。正式な設計書とは区別する。
- 資料を移動・改名した場合は、リポジトリ内のリンクと参照先を更新する。
