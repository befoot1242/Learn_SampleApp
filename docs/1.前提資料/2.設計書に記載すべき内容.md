# 設計書に記載すべき内容

## 共通事項

各設計書には、文書名、対象システム・機能、対象範囲、版または状態、根拠となる要件・資料を記載する。実装を根拠にする資料では、確認できた実装と設定、要件との差分、未確認・未定義の事項を区別する。根拠が確認できない仕様は推測で補わない。

## 資料種別ごとの記載内容

| 資料種別 | 記載すべき内容 |
|---|---|
| 要件資料 | 背景・目的、対象範囲、利用者と利用条件、機能要件、画面・操作の要件、外部連携要件、非機能要件、制約・前提、未決事項。要件案の場合は、案であることと確定状況を明記する。 |
| 基本設計書 | システム概要・構成、利用者と権限、機能一覧、画面一覧・遷移、内部・外部インターフェース概要、データ設計概要、認証・セキュリティ、監査・ログ、非機能・運用の概要、要件との対応・差分。詳細な項目仕様は詳細設計を参照する。 |
| API詳細設計 | エンドポイント、HTTPメソッド、認証・認可、要求・応答形式、項目と入力制約、正常・異常応答、共通エラー、呼び出し関係。 |
| DB詳細設計 | エンティティ・テーブル、項目名と型、必須・一意などの制約、主キー・外部キー、関連、更新規則、初期データ、未定義事項。 |
| 認証・認可詳細設計 | 認証方式、ログイン・ログアウト、セッション管理、CSRF等の保護、認可対象と判定条件、認証・認可エラー、監査記録。 |
| 外部API連携詳細設計 | 接続先と設定、外部APIの要求・応答、タイムアウト、再試行条件、エラー変換、冪等性、障害時の扱い。 |
| 処理フロー詳細設計 | 対象ユースケースごとの処理順、各コンポーネントの責務、分岐・例外、外部連携、データ更新、シーケンス図等。 |
| トランザクション詳細設計 | API・サービス単位の境界、参加するデータ更新、コミット・ロールバック条件、例外時の扱い、外部APIや監査記録との独立性。 |
| 画面別詳細設計 | 画面の目的・利用条件、画面項目、入力制約、操作、遷移、呼び出すAPI、表示状態、エラー表示、要件との差分。 |
| その他資料 | 図・画像等の用途と参照先。既存資料の評価では、期待する記載内容、確認できた記載箇所、充足状況、不足・未確認事項を対応付ける。 |

## 記載と評価の原則

- 要件に書かれた値と、実装または設定で確認した値を区別する。
- 仕様の記載には、可能な範囲で関連する要件・設計・実装への参照を付ける。
- 「未記載」は資料に記述がない状態、「未確認」は記述や実装を確認できず判定できない状態として区別する。
- カバレッジ評価は資料の記載状況を示すものであり、実装の正しさやテスト済みであることを保証しない。
