# S-01 ログイン画面 詳細設計

## 1. 画面概要

| 項目 | 内容 |
|---|---|
| 画面ID | S-01 |
| 画面名 | ログイン |
| URL | `/login` |
| 認証 | 不要（公開画面） |
| コンポーネント | `frontend/src/views/LoginView.vue` |
| レイアウト | 独立表示。認証後画面の共通ヘッダー・サイドメニューは表示しない |

![ログイン画面](../images/login.png)

## 2. 画面項目

| 項目 | UI | 必須 | 入力・表示仕様 |
|---|---|---|---|
| 画面タイトル | 見出し | - | 「取引管理システム」 |
| 案内文 | テキスト | - | ユーザIDとパスワードを入力する旨を表示 |
| ユーザID | テキスト入力 | 必須 | `autocomplete=username` |
| パスワード | パスワード入力 | 必須 | 入力文字をマスク。`autocomplete=current-password` |
| ログイン | 送信ボタン | - | 送信中は「ログイン中...」と表示し、ボタンを無効化 |
| エラー | エラーメッセージ領域 | - | 認証/APIエラー時に表示 |
| デモアカウント案内 | テキスト | - | 画面上にデモ用アカウント案内を表示 |

## 3. 操作・遷移

| 操作 | 処理 | 結果 |
|---|---|---|
| ログイン送信 | ユーザID・パスワードでログインAPIを呼び出す | 成功時は `redirect` クエリのパスへ遷移。文字列でなければ `/` へ遷移 |
| ログイン済みで `/login` にアクセス | Routerガードが認証状態を判定 | ホームへ遷移 |
| 未認証で保護画面にアクセス | Routerガードが遷移先を `redirect` に設定 | ログイン成功後、元のパスへ遷移 |

## 4. API

### ログイン

| 項目 | 内容 |
|---|---|
| メソッド・パス | `POST /api/auth/login` |
| 要求 | `{ "username": string, "password": string }` |
| 成功 | 認証済みユーザ情報（`authenticated`, `username`, `displayName`, `role`） |
| 認証失敗 | HTTP 401。`LOGIN_FAILED` または `USER_DISABLED` とメッセージを画面表示 |
| 認証方式 | Cookieセッション。CSRF保護対象のPOST |

### 初期認証状態確認

画面表示前のRouterガードがAuth Storeを初期化する。初回初期化時に `GET /api/auth/me` を呼び出し、認証状態を取得する。未認証の場合もAPIは `authenticated: false` を返す。通信失敗時は未認証として扱う。

## 5. 表示状態・エラー

- 送信前は入力フォームを表示する。
- 送信中は送信ボタンを無効化し、処理中ラベルを表示する。
- 認証失敗、無効化ユーザ、ネットワークエラー等は共通APIエラー変換後のメッセージをエラー領域に表示する。
- エラーの後に入力値は維持される。送信フラグは成功・失敗どちらでも解除する。

## 6. 要件案との対応

要件案はOAuthログイン開始操作を記載するが、現行実装はユーザID・パスワードを入力して自システムで認証する。要件案との差分であり、現行実装の仕様を本書に記載している。ログアウトは認証後の共通レイアウトから実行する。
